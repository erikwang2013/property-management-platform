### निष्कर्ष

- सभी इंटरफ़ेस 20 VU पर 0 विफलता, p95 < 220ms, स्वस्थ।
- **थ्रूपुट बाधा लगभग 230–250 rps**: 20 VU → 50 VU पर थ्रूपुट बढ़ने की बजाय सपाट (dashboard 227.9 → 226.9, fee 197 → 247), जबकि p95 लेटेंसी दोगुनी (~190ms → ~540ms)। सिंगल मशीन 32 worker पर प्रति worker लगभग 7–8 rps, PHP पूर्ण चेन (MySQL क्वेरी, Redis कैश राउंड-ट्रिप सहित) की सिंगल-कोर प्रोसेसिंग सीमा की विशेषता, कनेक्शन खत्म होना नहीं (कोई विफल अनुरोध नहीं)।
- सुझाव: सिंगल मशीन इस स्केल के लिए पर्याप्त (लगभग 2 करोड़ अनुरोध/दिन); उच्च थ्रूपुट चाहिए तो पहले क्षैतिज इंस्टेंस बढ़ाएं, फिर इंटरफ़ेस SQL और कैश हिट जांचें (नीचे देखें)।

## 3. स्लो क्वेरी समीक्षा

- शुल्क टेबल `management_fee_bill` / `management_fee_payment` इंडेक्स पूर्ण (paid_at, bill_id, owner_id, payment_number आदि), मुख्य क्वेरी के लिए इंडेक्स उपलब्ध।
- खोज बिंदु: शुल्क सूची `payment_number like %kw%` फजी सर्च (लीडिंग वाइल्डकार्ड), इंडेक्स उपयोग नहीं कर सकता, डेटा बड़ा होने पर यह शर्त फुल-टेबल स्कैन में बदल जाती है। कम आवृत्ति का एडमिन सर्च, फिलहाल नहीं संभाला; डेटा बढ़ने पर इनवर्टेड या प्रीफिक्स इंडेक्स में बदला जा सकता है।
- **MySQL slow_query_log OFF है**: सुझाव चालू करें और `long_query_time=1` सेट करें, वास्तविक स्लो SQL लगातार देखें (परीक्षण अनुमान पर निर्भर नहीं)। प्रोडक्शन में निष्पादित करें:
  ```sql
  SET GLOBAL slow_query_log = ON;
  SET GLOBAL long_query_time = 1;
  ```
- डैशबोर्ड एग्रीगेशन: हर कैश रीबिल्ड पर लगभग 8 COUNT एग्रीगेशन + 30 दिन समूह सांख्यिकी, एक बार रीबिल्ड सेकंड-लेवल लागत, Redis 5 मिनट कैश से अवशोषित (नीचे देखें), हॉट पाथ नहीं।

## 4. Redis कैश पुनः जांच

- डैशबोर्ड कैश `dashboard:data`: `setex 300`, हिट पर ~10ms, मिस होने पर रीबिल्ड सेकंड-लेवल। **समस्या: कोई राइट इनवैलिडेशन लॉजिक नहीं**, डेटा बदलने के बाद अधिकतम 5 मिनट स्टेल। सुझाव शुल्क/संपत्ति राइट इंटरफ़ेस में यह key हटाएं (एक पंक्ति `del dashboard:data`)।
- **कोई कैश पेनेट्रेशन सुरक्षा नहीं**: key समाप्त होने के क्षण 32 workers एक साथ रीबिल्ड करते हैं (8 एग्रीगेशन क्वेरी दोहराते हैं)। डेटा बड़ा होने पर सरल म्यूटेक्स जोड़ने का सुझाव (जैसे `set nx ex` लॉक + डबल-चेक)।
- अनुमति कैश `perm:{adminId}` 60s, व्यवहार सामान्य।
- शेष जांच आइटम: स्थानीय Redis में `dashboard:data` key कभी नहीं देखी गई (कई db में भी नहीं), लेकिन इंटरफ़ेस प्रतिक्रिया सामान्य और हिट लेटेंसी स्पष्ट रूप से कम। परीक्षण के दौरान कभी-कभी 403 «कोई अनुमति नहीं» (2 बार दिखा फिर स्थिर 200)। संदेह है स्थानीय मशीन पर कई Redis इंस्टेंस/पर्यावरण वेरिएबल कॉन्फ़िग ऑनलाइन से भिन्न है, लक्ष्य वातावरण में पुनः जांच आवश्यक, परीक्षण निष्कर्ष प्रभावित नहीं (स्थिर सेगमेंट में 0 विफलता)।
