## Overview

- Admin API runs on `http://localhost:8787`
- Owner API runs on `http://localhost:8788`
- Unified response format: `{"code": 0, "message": "success", "data": {...}}`
- All ID fields are transmitted hashids-encoded
- API version is expressed in the route itself (currently `/api/v1/*`), not via a request header
- Language is controlled via the `Accept-Language` request header (`zh-CN` / `en-US`, default `zh-CN`)

## Admin API (admin :8787)

### Public Endpoints — No Authentication

#### POST /api/v1/captcha/generate
Get a click captcha.

Request parameters: none

Response:
```json
{
  "code": 0,
  "data": {
    "key": "captcha_key_string",
    "image": "base64_encoded_png",
    "extra": { "targets": ["树", "鸟", "花"] }
  }
}
```

#### POST /api/v1/captcha/verify
Verify a click captcha.

Request parameters:
| Parameter | Type | Description |
|------|------|------|
| key | string | Captcha key, returned by generate |
| clicks | array | Click coordinates [{x, y}, ...] |

Response:
```json
{
  "code": 0,
  "data": { "valid": true }
}
```

On verification failure, `code` is 422 and `data.valid` is `false`.

#### POST /api/v1/auth/login
Admin login.

Request parameters:
| Parameter | Type | Description |
|------|------|------|
| username | string | Username |
| password | string | Password |
| captcha_key | string | Captcha key |
| clicks | array | Click coordinates [{x, y}, ...] |

Response:
```json
{
  "code": 0,
  "data": {
    "access_token": "eyJ...",
    "refresh_token": "eyJ...",
    "user": { "id": "aB3xK9mW...", "username": "admin", "real_name": "管理员" }
  }
}
```

#### POST /api/v1/auth/refresh
Refresh Token.

Request parameters:
| Parameter | Type | Description |
|------|------|------|
| refresh_token | string | Refresh token |

Response:
```json
{
  "code": 0,
  "data": { "access_token": "eyJ..." }
}
```

## Open API — API Key Authentication

Inbound read-only endpoints for third-party systems (property platform integration, data dashboards, etc.). Prefixed with `/open`, all read-only.

### Authentication

Each request must carry the `X-API-Key` request header, whose value is a Key generated by `scripts/gen_api_key.php` (64-bit hex; only the SHA-256 digest is stored in the database):

```bash
curl -H "X-API-Key: <your-key>" http://localhost:8788/open/v1/announcements
```

- A missing or invalid Key returns `401` (`{"code":401,"message":"无效的API Key","data":[]}`)
- Key management: generate with `php scripts/gen_api_key.php [--name=purpose]`; to disable/delete, operate directly on the `management_api_key` table (`status=0` disables, key becomes invalid immediately)

### Endpoints

#### GET /open/v1/announcements — Announcement list

Parameters: `page` (default 1), `category` (optional). Response structure is identical to `/service/v1/announcements`.

```bash
curl -H "X-API-Key: <your-key>" "http://localhost:8788/open/v1/announcements?page=1"
```

#### GET /open/v1/bills — Bill query

Parameters: `bill_number` (required, bill number). Returns a single bill's details (fee type, room number, arrears amount). Returns 404 if not found.

```bash
curl -H "X-API-Key: <your-key>" "http://localhost:8788/open/v1/bills?bill_number=B202608160001"
```

#### GET /open/v1/repairs — Repair status query

Parameters: `order_number` (required, repair order number). Returns the repair order's current status and progress timeline (`progress` array). Returns 404 if not found.

```bash
curl -H "X-API-Key: <your-key>" "http://localhost:8788/open/v1/repairs?order_number=R202608160001"
```

## Error Codes

| code | Meaning | Description |
|------|------|------|
| 0 | Success | Normal response |
| 400 | Bad request | Incorrect parameter format |
| 401 | Unauthenticated | Token missing/expired/invalid/blacklisted |
| 403 | Forbidden | User role lacks the required permission / account disabled |
| 404 | Not found | Resource not found |
| 405 | Method not allowed | HTTP method other than GET/POST/PUT/DELETE/OPTIONS |
| 413 | Payload too large | Exceeds 10MB |
| 415 | Unsupported media type | Content-Type is not JSON or form-urlencoded |
| 422 | Validation failed | Form parameters violate rules / password confirmation failed / captcha error |
| 429 | Too many requests | Rate limit triggered / account locked |
| 500 | Server error | Unexpected exception |

## Rate Limit Response Headers

When the rate limit is triggered, 429 is returned with the following response headers:

| Response Header | Description |
|--------|------|
| X-RateLimit-Limit | Rate limit count |
| X-RateLimit-Remaining | Remaining count |
| X-RateLimit-Reset | Reset time (Unix timestamp) |
| Retry-After | Recommended retry wait in seconds |
