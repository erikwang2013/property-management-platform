## 2. Пробелы в безопасности и качестве (security-auditor)

**18 уровней защиты: 16/18 подтверждены**, реализация соответствует SECURITY_ARCHITECTURE.md (код подтверждения, повторное подтверждение, poster, SecurityFilter, AES-256-CBC, JWT, лимит сессий, блокировка аккаунта, RBAC, ограничение частоты, hashids, шифрование полей, маскирование, журнал аудита, CSP).

**Два несоответствия (оба P1 исправлены):**
1. ~~security-php установлен только в service~~ → подключён в SecurityFilter обеих сторон (в admin и service слой глубокого сканирования 4b, ленивая инициализация SecurityGuard, при блокировке — запись и эскалация)
2. ~~водяной знак PDF не реализован~~ → проверено: 18-й уровень водяного знака в ExportController реализован (ExportController.php:179,206), ложное срабатывание аудита

**Самый высокий риск: жёстко закодированные запасные ключи (исправлено).** EncryptionService/конфигурация шифрования полностью переведены на fail-fast (при отсутствии или change-me — ошибка при старте); жёсткая кодировка и случайные запасные ключи в encryptable/jwt удалены; ключи .env — сгенерированные настоящие случайные значения, CI загружает копию .env.example. Пароли DB/Redis остаются заполнителями — это учётные данные развёртывания, их внедряет сторона развёртывания.

**Инженерные недочёты (P1 дополнено):** в CI добавлены задания phpstan (Level 5 + baseline)、шлюз покрытия PHPUnit обеих сторон (замеренная база admin 1.66% / service 3.21%, шлюз защищает от регрессии с нулевой инструментацией)、сканирование утечек ключей gitleaks (.gitleaks.toml пропускает шаблоны окружения).

**Проверка высокорисковых паттернов:** eval( только Redis::eval (безопасно)、exec 3 места (контроллеры мониторинга/установки)、md5( только хеш чёрного списка токенов、SQL полностью через query builder — риска голой конкатенации нет.
