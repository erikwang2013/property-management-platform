## 機能モジュール比較

### ベーシック版 (Lite)

コアの不動産管理。管理画面共通システム + 10 のコア業務モジュールを含む。

**管理端**: ダッシュボード、ユーザー/ロール/権限/設定/ログ CRUD、コミュニティ/棟/部屋/間取りタイプ/不動産/所有者/テナント/料金/修理依頼/お知らせ CRUD

**所有者端**: 登録/ログイン、ホーム、マイ不動産、請求書支払い、修理依頼提出/評価、お知らせ閲覧、個人情報

---

### スタンダード版 (Standard)

ベーシック版に 6 つの補助業務モジュール + パネル可視化 + データエクスポートを追加。

**管理端の新規追加**: 駐車スペース/車両 CRUD、設備台帳+メンテナンス、苦情処理+フォローアップ、来訪者承認、契約管理、収支管理+統計

**所有者端の新規追加**: マイ車両/駐車スペース、駐車記録、来訪者予約/通行コード

---

### フル版 (Full)

スタンダード版に高度モジュール + 12 の拡張機能を追加。

**管理端の新規追加**: 巡回ルート+記録、清掃エリア+記録、緑化エリア+維持管理、コミュニティイベント管理、エネルギー計器+検針、スタッフ管理、通知テンプレート+送信、承認エンジン、決済注文+返金、投票管理+SLA ルール+督促戦略+巡回点検タスク+モール管理+顔認証審査+グループ管理+ナレッジベース

**所有者端の新規追加**: コミュニティイベント申し込み、駐車/来訪者予約、メッセージ通知、投票+集計、商品閲覧+注文、スマートQ&A、顔認証登録

```
ベーシック版 (Lite)
  │
  │  + 6補助モジュール + パネル + エクスポート
  ▼
スタンダード版 (Standard)
  │
  │  + 6高度モジュール + 12拡張機能
  ▼

```

アップグレードは対応するバッチの SQL 移行ファイルを実行するだけで、データ移行や破壊的変更は不要です。

## デモフロー

**準備**：`docs/install.sql` を実行済み（全量テーブル構造、全バージョンのテーブルを含む）；`admin/.env` にデータベース接続を設定済み。バージョン差異はルート登録と機能可視性にあり、テーブル構造は全量で統一。

### ベーシック版 (Lite)

1. デモデータ実行：`cd admin && php ../scripts/demo_data.php`（冪等、繰り返し実行可）
2. デモデータ範囲：コミュニティ/棟/部屋/間取りタイプ/不動産/所有者/テナント/料金/請求書/お知らせ + デモアカウント、Lite コアモジュールをカバー
3. 見どころ：管理端ダッシュボード + ユーザー/ロール/権限/設定/ログ + 不動産/所有者/テナント/料金/修理依頼/お知らせ CRUD；所有者端登録/ログイン、ホーム、マイ不動産、請求書支払い、修理依頼、お知らせ
4. ルート差異：Lite グループのみ登録、`edition_supports('standard'/'full')` で包まれたブロックは登録されない（`admin/config/route.php`）

### スタンダード版 (Standard)

1. デモデータ実行：`cd admin && php ../scripts/demo_data.php`（冪等、繰り返し実行しても不足分の補完のみで重複作成しない）
2. 補助モジュールのデータ量は少なく、駐車/設備/苦情/来訪者/契約/収支はデモ入力で少量で十分
3. 見どころ：管理端に駐車スペース/車両、設備台帳+メンテナンス、苦情処理+フォローアップ、来訪者承認、契約管理、収支管理+統計を追加；所有者端にマイ車両/駐車スペース、駐車記録、来訪者予約/通行コードを追加
4. ルート差異：`edition_supports('standard')` グループを追加、Lite グループは保持

### フル版 (Full)

1. デモデータ実行：`cd admin && php ../scripts/demo_data.php`（冪等）
2. 高度モジュール（決済/承認/投票/モール/巡回点検/顔認証/グループ/ナレッジベース）のデモデータは必要に応じて入力、またはデモアカウントで直接作成
3. 見どころ：Standard に加え巡回/清掃/緑化/エネルギー/スタッフ/通知テンプレート/承認エンジン/決済注文/投票/SLA/督促/巡回点検/モール/顔認証/グループ/ナレッジベースを追加；所有者端はイベント申し込み、メッセージ通知、投票、モール注文、スマートQ&A、顔認証登録
4. ルート差異：全量登録、`edition_supports('full')` グループが有効（`admin/config/route.php`）

### バージョン切替

```bash
# admin/.env に対象バージョンを設定（段階累進、full は全機能を含む）
EDITIONS=lite|standard|full

# webman を再起動して反映（コンテナデプロイ: docker compose restart app；ベアメタル: php start.php restart）
```

- 設定 fail-fast：`EDITIONS` の値が無効なら直接エラー（`admin/config/edition.php`）、誤ったバージョンに黙ってフォールバックしない。
- デモデータスクリプトは冪等で、バージョン切替時に DB クリア不要；Standard/Full モジュールのデータ量は少なく、実際の業務入力で十分。
